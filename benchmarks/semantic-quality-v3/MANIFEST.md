## 7. Anti-Overlap Verification

**Method.** Each V3 prompt checked against (a) v2 dev (54) + v2 holdout (18), (b) v1 calibration (48) + v1 holdout (12) using:
1. **Exact-string check:** whitespace-normalized, lowercased full-string equality.
2. **Token-overlap check:** shared content tokens after lowercasing, umlaut normalization, stopword removal. Flagged at ≥8 shared content tokens (conservative; generic task vocabulary such as `extract/return/json/below/text` naturally overlaps at 6–7 tokens across extraction tasks and is not a paraphrase).

**Results.**

| Check | Result |
|---|---:|
| Exact-string overlaps | 0 |
| Max shared content tokens | 7 |
| Pairs flagged at ≥8 shared tokens | 0 |
| Pairs flagged at ≥6 shared tokens (reviewed) | 15 generic collisions (shared task verbs + input/output phrasing such as `extract/return/json/with/keys/below/text`), manually reviewed — no paraphrase of a specific prior case (different domains, different deliverables). |

The highest overlaps are coincidental vocabulary collisions on generic words — not paraphrases. The only intentionally high-overlap pair is H1/H2 (designed contrast pair sharing core instruction by construction; internal overlap excluded from inter-set reporting).

## 8. Rubric Pin

`benchmarks/semantic-quality-v3/rubric.json` is byte-identical to `benchmarks/semantic-quality/rubric.json` v1.0.0 (pinned, read-only).

## 9. Holdout Secrecy

The 24 holdout cases are a **locked holdout**. Holdout inputs are committed under `cases/holdout.json` in this repository for the cleanroom run; the final holdout **gold** is NOT committed. Gold will be generated by blind independent judges (Phase 12) and remains sealed until candidate freeze. No holdout gold exists on disk before freeze.
